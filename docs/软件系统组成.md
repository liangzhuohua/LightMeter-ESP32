# ESP32-S3 智能测光表软件系统组成

## 一、系统概述

本项目是基于ESP32-S3N16R8微控制器（16MB Flash，8MB PSRAM）的智能摄影测光表系统，集成460x460分辨率AMOLED触摸屏、WiFi连接、电池管理、多传感器接口等功能，采用FreeRTOS实时操作系统和LVGL图形库构建用户界面。

### 1.1 系统特性

- 支持入射式测光计算（基于环境光传感器）
- 多种曝光模式：手动模式、自动模式、风景模式、人像模式
- 1/3 EV和1/2 EV步进支持
- WiFi联网获取天气、位置、时间
- OTA固件升级
- 深度睡眠低功耗管理
- 电池电量监测与充电状态检测

### 1.2 硬件平台

| 组件 | 型号/规格 | 接口 |
|------|----------|------|
| 微控制器 | ESP32-S3N16R8 | - |
| 显示屏 | 460×460 QSPI AMOLED | SPI3_HOST |
| 触摸控制器 | CST820 | I2C |
| 环境光传感器 | VEML7700 | I2C |
| 电池电量计 | MAX17055 | I2C |
| 充电管理 | TP4056 | GPIO |
| 唤醒按键 | - | GPIO9 |

### 2.3 分层调用规则

本系统采用务实分层策略，根据模块复杂度和业务需求决定是否引入中间层（app_xxx），而非强制统一。具体规则如下：

#### 2.3.1 分层规则定义

| 规则类型 | 是否需要中间层 | 说明 |
|---------|--------------|------|
| 单一硬件 + 无业务逻辑 | **不需要** | 直接调用hw_xxx，避免无意义的转发 |
| 多硬件合并 | **需要** | 必须有app_xxx统一接口 |
| 复杂业务逻辑 | **需要** | 业务逻辑不应放在hw层 |
| 数据结构管理 | **需要** | 需要专门的存储管理层 |

#### 2.3.2 模块分类与调用路径

```
┌─────────────────────────────────────────────────────────────────┐
│                    app_controller（调度中心）                    │
└─────────────────────────────┬───────────────────────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
        ▼                     ▼                     ▼

┌───────────────┐      ┌───────────────┐      ┌───────────────┐
│  直接调用HW   │      │  多硬件/业务  │      │  数据管理    │
│  (无中间层)   │      │  (有中间层)   │      │  (有中间层)  │
├───────────────┤      ├───────────────┤      ├───────────────┤
```

#### 2.3.3 各模块分层依据详解

**直接调用HW层（无中间层）：**

| 模块 | 代码行数 | 分层依据 |
|------|---------|---------|
| `hw_wifi.c` | 410行 | WiFi是单一硬件模块，状态管理属于硬件范畴，无额外业务逻辑需要封装 |
| `hw_veml7700.c` | 108行 | 环境光传感器是单一硬件，仅提供lux值读取，无业务处理 |
| `hw_wakeup_key.c` | 148行 | 按键检测是单一硬件，长按检测和睡眠唤醒配置属于硬件操作 |

**需要中间层：**

| 模块 | 代码行数 | 分层依据 |
|------|---------|---------|
| `app_battery.c` | 64行 | 合并两个硬件（MAX17055电量计 + TP4056充电检测），提供统一电池状态接口；包含满充校准逻辑（TP4056充满时校准MAX17055 SOC为100%） |
| `app_nvs_storage.c` | 754行 | 管理具体业务数据结构（相机参数、镜头参数、WiFi配置、位置信息、天气缓存、同步时间戳）；hw_nvs仅提供底层NVS操作，不了解业务数据语义 |

#### 2.3.4 设计优势

这种务实分层策略的优势：

1. **避免过度抽象**：对于简单硬件（如VEML7700仅读取lux值），强行加中间层会变成无意义的转发函数，增加代码量但不增加价值
2. **保持必要抽象**：对于多硬件合并（电池）和复杂数据管理（NVS），中间层提供清晰的统一接口和业务逻辑封装
3. **代码量可控**：不引入不必要的层，减少维护负担
4. **职责清晰**：hw层专注硬件操作，app层处理业务逻辑和数据管理，controller层负责调度协调

#### 2.3.5 app_controller调用关系表

| 功能 | 调用路径 | 是否有中间层 | 原因 |
|------|---------|-------------|------|
| WiFi操作 | `app_controller → hw_wifi` | 无 | 单一硬件，状态管理属于硬件范畴 |
| 环境光读取 | `app_controller → hw_veml7700` | 无 | 单一硬件，仅读取数值 |
| 唤醒按键 | `app_controller → hw_wakeup_key` | 无 | 单一硬件，按键检测 |
| 电池状态 | `app_controller → app_battery → hw_max17055/hw_tp4056` | 有 | 合并两个硬件 + SOC校准逻辑 |
| 数据存储 | `app_controller → app_nvs_storage → hw_nvs` | 有 | 复杂业务数据结构管理 |
| 曝光计算 | `app_controller → app_exposure_calc` | 有 | 核心业务算法 |

#### 6.1.3 核心算法

```c
// 照度转EV值（入射式）
float exposure_lux_to_ev_incident(float lux, float iso)
{
    // EV = log2(Lux / 2.5) + log2(ISO / 100)
    return log2f(lux / 2.5f) + log2f(iso / 100.0f);
}

// 光圈优先模式
float exposure_aperture_priority(float lux, float iso, float ev_comp, float aperture)
{
    float ev = exposure_lux_to_ev_incident(lux, iso) + ev_comp;
    // 计算快门时间：t = (f² / A) × 2^(-EV)
    return (aperture * aperture) * powf(2.0f, -ev) * 0.01f;
}

// 快门优先模式
float exposure_shutter_priority(float lux, float iso, float ev_comp, float shutter)
{
    float ev = exposure_lux_to_ev_incident(lux, iso) + ev_comp;
    // 计算光圈值：f = sqrt(t × 2^EV × 100)
    return sqrtf(shutter * powf(2.0f, ev) * 100.0f);
}

// 自动曝光计算
void exposure_auto(uint32_t lux, float iso, uint8_t auto_mode,
                   LEN len, CAM cam, float ev_comp,
                   float* aperture, float* shutter, ExposureFlags* flags)
{

    // 根据模式和约束计算最佳曝光组合
}
```

### 6.6 OTA升级模块

#### 6.6.1 分区架构

系统采用双OTA分区设计，实现安全的A/B切换升级机制：

```
┌─────────────────────────────────────────────────────────────┐
│                    Flash分区布局 (16MB)                      │
├─────────────────────────────────────────────────────────────┤
│ 分区名称    │ 类型  │ 偏移地址   │ 大小   │ 说明           │
├─────────────┼───────┼────────────┼────────┼────────────────┤
│ nvs         │ data  │ 0x9000     │ 24KB   │ 非易失存储     │
│ phy_init    │ data  │ 0xf000     │ 4KB    │ RF校准数据     │
│ ota_0       │ app   │ 0x10000    │ 3MB    │ OTA分区A       │
│ ota_1       │ app   │ 0x310000   │ 3MB    │ OTA分区B       │
│ ota_data    │ data  │ 自动分配   │ 8KB    │ 启动分区记录   │
└─────────────────────────────────────────────────────────────┘
```

**核心机制：ota_data分区**

`ota_data` 分区存储启动配置信息，记录当前应该从哪个分区启动：

```
┌─────────────────────────────────────────────────────────────┐
│                   ota_data 分区结构                         │
├─────────────────────────────────────────────────────────────┤
│  偏移    │ 字段              │ 说明                        │
├──────────┼───────────────────┼─────────────────────────────┤
│  0x00    │ ota_seq           │ 启动序列号（1=ota_0, 2=ota_1）│
│  0x04    │ ota_label[16]     │ 分区标签字符串              │
│  0x14    │ crc32             │ CRC校验值                   │
└─────────────────────────────────────────────────────────────┘

启动流程：
Bootloader ──读取──▶ ota_data ──确认──▶ 从ota_0或ota_1启动
```

**A/B切换原理：**

```
升级前（运行ota_0）：

       ┌──────────────────────────────┐
       │      Bootloader              │
       │  读取ota_data → seq=1 → ota_0│
       └──────────────┬───────────────┘
                      ▼
  ┌─────────┐   ┌─────────┐         ┌─────────┐
  │  ota_0  │ ◀─ │ota_data │         │  ota_1  │
  │ (当前)  │引导│ seq=1   │         │ (空闲)  │
  └─────────┘   └─────────┘         └─────────┘

升级中（固件写入ota_1，ota_data不变）：

              ┌─────────┐         ┌─────────┐
              │ota_data │         │  ota_1  │
  ┌─────────┐ │ seq=1   │         │         │ ◀── ┌─────────┐
  │  ota_0  │ │ (不变)  │         │ 写入新  │     │ HTTP    │
  │ (当前)  │ └─────────┘         │ 固件    │     │ 上传    │
  └─────────┘                     │         │     └─────────┘
       ▲                          └─────────┘
       │
    继续运行旧固件

写入完成，校验固件（esp_ota_end() 校验完整性）：

  ┌─────────┐         ┌─────────┐         ┌─────────┐
  │  ota_0  │         │ota_data │         │  ota_1  │
  │ (当前)  │         │ seq=1   │         │ 新固件  │
  └─────────┘         └─────────┘         └─────────┘
                       (不变)               ▲
                                            │
                                    esp_ota_end()校验中
                                    SHA256 / 镜像头 / 大小

校验通过，切换启动分区（esp_ota_set_boot_partition() 更新ota_data）：

  ┌─────────┐         ┌─────────┐   引导   ┌─────────┐
  │  ota_0  │         │ota_data │ ───────▶ │  ota_1  │
  │ (旧固件)│         │ seq=1→2 │          │ (新固件)│
  └─────────┘         └─────────┘          └─────────┘
                       seq已更新             esp_restart()
                       下次启动将引导ota_1

重启后（Bootloader读取ota_data，从ota_1启动）：

       ┌──────────────────────────────┐
       │      Bootloader              │
       │  读取ota_data → seq=2 → ota_1│
       └──────────────┬───────────────┘
                      ▼
  ┌─────────┐   ┌─────────┐         ┌─────────┐
  │  ota_0  │   │ota_data │         │  ota_1  │
  │ (空闲)  │   │ seq=2   │ ──────▶ │ (当前)  │
  └─────────┘   └─────────┘  引导   └─────────┘
```

#### 6.6.3 关键API调用

```c
// 获取下一个可用的OTA分区（非当前运行的分区）

// 若当前运行ota_0，返回ota_1；若当前运行ota_1，返回ota_0

// 开始OTA写入

// 分块写入固件数据

// 设置下次启动分区（更新ota_data）
```

## 八、深度睡眠与电源管理

### 8.1 系统电源状态机

整个系统在三种电源状态之间切换：

```
                          ┌──────────────────────────┐
                          │       正常运行态          │
                          │  (Active)                │
                          │                          │
                          │  CPU运行 / 显示工作      │
                          │  WiFi可选 / 传感器工作   │
                          │  功耗：~150-400mA        │
                          └───────────┬──────────────┘
                                      │
                    ┌─────────────────┼─────────────────┐
                    │                 │                 │
                    ▼                 ▼                 ▼
          ┌──────────────────┐  ┌────────────┐  ┌──────────────┐
          │   触发睡眠条件   │  │ 充电接入   │  │ 按键唤醒    │
          │                  │  │ (TP4056    │  │ (GPIO9      │
          │ • 长按按键3秒    │  │  检测到)   │  │  低电平)    │
          │ • 主动触发睡眠   │  └──────┬─────┘  └──────┬───────┘
          └────────┬─────────┘         │               │
                   │                   │               │
                   ▼                   ▼               │
          ┌──────────────────────────────────────────┐ │
          │           深度睡眠态                      │ │
          │  (Deep Sleep)                            │ │
          │                                          │ │
          │  CPU关闭 / 显示关闭                      │◀┘
          │  WiFi断开 / 传感器关闭                   │
          │  RTC保持运行(时间)/ ULP可选               │
          │  功耗：~10-50μA                          │
          └──────────────────────────────────────────┘
```

### 8.2 睡眠触发条件

- **长按唤醒按键超过3秒** — GPIO9检测到低电平持续3秒，触发中断
- **用户主动触发睡眠** — 通过UI菜单选择进入睡眠

### 8.3 睡眠流程

深度睡眠的下电顺序（从软件到硬件，逐级关闭）：

```
                          触发睡眠
                             │
                             ▼
              ┌─────────────────────────────┐
              │  Step 1: 保存时间           │
              │  将当前时间写入RTC寄存器     │
              │  (gettimeofday → RTC)        │
              └─────────────┬───────────────┘
                            │
                            ▼
              ┌─────────────────────────────┐
              │  Step 2: 关闭GUI层          │
              │  AMOLED → oled_enter_sleep()│
              │  触摸IC → cst820睡眠        │
              └─────────────┬───────────────┘
                            │
                            ▼
              ┌─────────────────────────────┐
              │  Step 3: 关闭外设           │
              │  VEML7700 → shutdown()      │
              │  MAX17055 → sleep()         │
              └─────────────┬───────────────┘
                            │
                            ▼
              ┌─────────────────────────────┐
              │  Step 4: 断开网络           │
              │  WiFi → disconnect()        │
              │  WiFi → stop()              │
              └─────────────┬───────────────┘
                            │
                            ▼
              ┌─────────────────────────────┐
              │  Step 5: 释放引脚           │
              │  QSPI/GPIO引脚 → RTC GPIO   │
              │  设置为高阻输入              │
              └─────────────┬───────────────┘
                            │
                            ▼
              ┌─────────────────────────────┐
              │  Step 6: 配置唤醒源         │
              │  ext0_wakeup(GPIO9, 0)     │
              │  (GPIO9=低电平时唤醒)      │
              └─────────────┬───────────────┘
                            │
                            ▼
              ┌─────────────────────────────┐
              │  Step 7: 进入深度睡眠       │
              │  esp_deep_sleep_start()     │
              │  ─── 系统掉电，等待唤醒 ─── │
              └─────────────────────────────┘
```

释放的GPIO引脚明细：

```
┌──────────┬──────────────┬───────────────────────────┐
│ GPIO引脚  │ 外设         │ 释放后状态                │
├──────────┼──────────────┼───────────────────────────┤
│ GPIO4    │ QSPI CS      │ RTC_GPIO, 上拉/下拉禁用   │
│ GPIO5    │ QSPI SCLK    │ RTC_GPIO, 上拉/下拉禁用   │
│ GPIO6    │ QSPI D0      │ RTC_GPIO, 上拉/下拉禁用   │
│ GPIO7    │ QSPI D1      │ RTC_GPIO, 上拉/下拉禁用   │
│ GPIO8    │ QSPI D2/D3   │ RTC_GPIO, 上拉/下拉禁用   │
│ GPIO9    │ 唤醒按键     │ RTC_GPIO, 唤醒源          │
└──────────┴──────────────┴───────────────────────────┘
```

### 8.4 启动/唤醒流程

`app_controller_wakeup_init()` 在系统每次启动时被调用，根据唤醒原因选择初始化路径：

```
                              │

                     ┌────────────────────┐
                     │  main()            │
```

## 十四、总结

本系统采用分层架构设计，具有良好的模块化特性：

1. **表示层**：LVGL图形界面，提供直观的触摸交互
2. **应用层**：业务逻辑实现，包括测光计算、网络服务、数据管理
3. **硬件抽象层**：屏蔽硬件细节，提供统一接口
4. **驱动层**：外设驱动实现
5. **框架层**：ESP-IDF提供的底层支持

系统特点：
- **实时性**：FreeRTOS任务调度，优先级合理分配
- **可靠性**：看门狗、异常处理、NVS持久化
- **低功耗**：深度睡眠、外设管理、动态功耗控制
- **可维护性**：清晰的模块划分、统一的接口规范
- **可扩展性**：模块化设计、OTA升级支持
